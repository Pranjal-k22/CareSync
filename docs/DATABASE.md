# 🗄️ CareSync — Database Schema & Data Architecture

## Database Technology
- **Database Engine**: PostgreSQL 15+ (Hosted via **Supabase**).
- **ORM / Interface**: Supabase Python Client (`@supabase/supabase-js` on frontend, `supabase-py` on backend).
- **Security**: PostgreSQL Row Level Security (RLS) policies.

---

## Canonical Database Schema (`backend/supabase_schema.sql`)

### 1. `users` Table
Stores user accounts, credentials, hashed passwords, and system roles.

| Column Name | Data Type | Constraints / References | Purpose |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, Default `gen_random_uuid()` | Unique user identifier |
| `email` | `TEXT` | `UNIQUE`, `NOT NULL` | User email / login identifier |
| `password_hash` | `TEXT` | `NOT NULL` | PBKDF2-SHA256 hashed password |
| `role` | `TEXT` | `NOT NULL`, Check (`admin`, `doctor`, `patient`, `staff`) | User system role |
| `full_name` | `TEXT` | `NOT NULL` | User display name |
| `doctor_id` | `TEXT` | `UNIQUE`, Optional | Doctor ID (e.g., `DOC-8891`) |
| `patient_id` | `TEXT` | `UNIQUE`, Optional | Patient ID (e.g., `PAT-1001`) |
| `created_at` | `TIMESTAMPTZ` | Default `NOW()` | Account creation timestamp |

---

### 2. `patients` Table
Stores de-identified demographic and clinical patient admission records.

| Column Name | Data Type | Constraints / References | Purpose |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, Default `gen_random_uuid()` | Record UUID |
| `patient_id` | `TEXT` | `UNIQUE`, `NOT NULL` | De-identified clinical ID (e.g., `PAT-1001`) |
| `first_name` | `TEXT` | `NOT NULL` | De-identified first name |
| `last_name` | `TEXT` | `NOT NULL` | De-identified last name |
| `age` | `INTEGER` | `NOT NULL` | Patient age |
| `gender` | `TEXT` | Check (`Male`, `Female`, `Other`) | Patient gender |
| `admission_type` | `TEXT` | Check (`Emergency`, `Elective`, `Urgent`) | Hospital admission classification |
| `comorbidity_index` | `NUMERIC` | Default `0.0` | Clinical comorbidity severity score |
| `assigned_doctor_id` | `TEXT` | References `users(doctor_id)` | Assigned physician ID |
| `created_at` | `TIMESTAMPTZ` | Default `NOW()` | Record creation timestamp |

---

### 3. `vitals` Table
Stores IoT telemetry sensor readings (MAX30102, DHT22, DS18B20) from MQTT ingestion pipeline and manual nurse vitals entry.

| Column Name | Data Type | Constraints / References | Purpose |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, Default `gen_random_uuid()` | Vitals entry UUID |
| `patient_id` | `TEXT` | References `patients(patient_id)` | Linked patient ID (e.g. `PAT-1001`) |
| `device_id` | `TEXT` | `NOT NULL` | Hardware device identifier (e.g. `node-9901`) |
| `hospital_id` | `TEXT` | `NOT NULL` | Multi-tenant hospital ID (e.g. `hosp-001`) |
| `heart_rate` | `NUMERIC` | `NOT NULL` | Beats per minute (BPM) |
| `spo2_pct` / `spo2` | `NUMERIC` | `NOT NULL` | Blood oxygen saturation (%) |
| `temperature_c` / `temperature` | `NUMERIC` | `NOT NULL` | Body temperature in Celsius |
| `room_temp` | `NUMERIC` | Optional | Room ambient temperature (°C) |
| `humidity` | `NUMERIC` | Optional | Room relative humidity (%) |
| `finger_detected` | `BOOLEAN` | Default `true` | MAX30102 optical finger contact status |
| `seq` | `INTEGER` | Default `0` | Packet sequence counter |
| `source` | `TEXT` | Default `mqtt_ingestion` | Ingestion source identifier |
| `recorded_at` / `timestamp` | `TIMESTAMPTZ` | Default `NOW()` | Telemetry timestamp |

---

### 4. `prediction_history` Table
Stores immutable audit history for all AI predictions generated by deterioration and disease engines.

| Column Name | Data Type | Constraints / References | Purpose |
| :--- | :--- | :--- | :--- |
| `id` | `UUID` | `PRIMARY KEY`, Default `gen_random_uuid()` | Audit record UUID |
| `prediction_id` | `TEXT` | `UNIQUE`, `NOT NULL` | Unique prediction identifier (e.g. `PRED-1001`) |
| `patient_id` | `TEXT` | References `patients(patient_id)` | Associated patient ID |
| `prediction_type` | `TEXT` | Check (`Deterioration`, `Disease/Flu`, `Unified`) | Model category |
| `risk_score` | `NUMERIC` | `NOT NULL` | Risk score percentage (0-100%) |
| `risk_level` | `TEXT` | Check (`LOW`, `MEDIUM`, `HIGH`, `CRITICAL`) | Categorical risk grade |
| `model_version` | `TEXT` | `NOT NULL` | Active model version string (e.g. `v1.0`) |
| `top_factors` | `JSONB` | `NOT NULL` | SHAP feature attribution array |
| `created_at` | `TIMESTAMPTZ` | Default `NOW()` | Prediction timestamp |

---

### 5. `audit_logs` Table
Immutable security and HIPAA audit trail logging all user authentication, profile modifications, data exports, and prediction requests.

| Column Name | Data Type | Purpose |
| :--- | :--- | :--- |
| `id` | `UUID` | Primary Key |
| `user_id` | `TEXT` | Authenticated user ID or `guest@caresync.com` |
| `action` | `TEXT` | Event action string (`LOGIN`, `DISEASE_PREDICTION`, `UPDATE_BEDS`) |
| `resource_type` | `TEXT` | Resource category (`AUTH`, `DISEASE_ENGINE`, `ICU_BEDS`) |
| `entity_id` | `TEXT` | Affected entity ID |
| `details` | `JSONB` | Contextual event metadata JSON |
| `ip_address` | `TEXT` | Client IPv4/IPv6 address |
| `timestamp` | `TIMESTAMPTZ` | Immutable UTC event timestamp |

## Security & Row Level Security (RLS) Policies

```sql
-- Enable Row Level Security on all tables
ALTER TABLE users ENABLE ROW LEVEL SECURITY;
ALTER TABLE patients ENABLE ROW LEVEL SECURITY;
ALTER TABLE vitals ENABLE ROW LEVEL SECURITY;
ALTER TABLE prediction_history ENABLE ROW LEVEL SECURITY;
ALTER TABLE audit_logs ENABLE ROW LEVEL SECURITY;

-- Patients Isolation Policy
CREATE POLICY "Clinicians can view all patients" ON patients
  FOR SELECT USING (auth.jwt() ->> 'role' IN ('admin', 'doctor', 'staff'));

-- Immutable Audit Log Policy (INSERT ONLY)
CREATE POLICY "Insert-only audit trail" ON audit_logs
  FOR INSERT WITH CHECK (true);
```
